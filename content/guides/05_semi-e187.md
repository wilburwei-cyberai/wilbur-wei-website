先講三件事：SEMI E187 的正式名稱是 Specification for Cybersecurity of Fab Equipment，是晶圓廠設備的資安基準；SEMI 自己說明，這類標準是產業的自願性技術協議，不是政府法令；對老闆來說，真正會影響營運的，通常是客戶有沒有把它寫進訂單或供應鏈要求——那可能關係到能不能出貨、能不能過查核，以及客戶還信不信任你。

## 它是什麼、目前是哪一版

SEMI 半導體資安標準頁寫明：E187 於 2022 年 1 月發布，作為設備在設計、運作和維護上的基礎要求，範圍包含作業系統支援、網路安全、端點防護和安全監控。用老闆的話講，就是系統還有沒有人維護、網路怎麼守、設備上的電腦本身怎麼防，以及出了事能不能查到紀錄。

SEMI 商店頁標示目前版本為 **E187-0122**，並標為 Current。同一頁的摘要說明：這份標準定義高階、基礎的資安要求，作為晶圓廠設備在設計階段就納入安全、並在營運和維護時持續防護的基準。

請注意：產業後續可能修訂標準。SEMI 公開的修訂提案（SNARF，文件編號 7317）顯示，針對 E187-0122 的修訂工作已在進行，討論包含擴大範圍與安全等級等方向。**提案或草案不是已經生效的版本。** 客戶或合約要求哪一版，要以雙方約定和 SEMI 當時標示為 Current 的版本為準。本稿撰寫時（2026-11-16）商店頁仍列 E187-0122 為現行版。

SEMI 也另有相關標準，例如 E188（惡意程式防護與設備整合）、E191（運算裝置資安狀態通報）。它們和 E187 是同一家族、但不是同一份文件。客戶若點名的是 E187，先對 E187；若還要求其他編號，再分開對。

## 誰會被要求、哪些設備算進去

SEMI 商店頁寫明：這份標準打算由**向晶圓廠提供設備或服務的單位**來應用，例如設備供應商和系統整合商。它處理的是半導體生產設備和自動化物料搬運系統，在設計、運作和維護上的資安措施。

適用的裝置是：晶圓廠設備上、安裝 Microsoft Windows 或 Linux 的運算裝置。

**不適用於：** 可程式邏輯控制器（PLC）、監督控制與資料擷取系統（SCADA），以及透過感測與致動網路接在它們上面的裝置。

因此，不是「公司裡每一台電腦」都自動落在 E187 裡，也不是「做半導體相關生意就一定被這份標準直接管制」。實際會不會被要求，常見情況是：

- 客戶（例如晶圓廠或上一階設備商）把 E187 寫進合約、規格書或供應商稽核問卷；
- 你提供的設備或服務，正好落在上述適用範圍。

若客戶要的是政府法令、上市櫃規定或 ISO 27001，那是不同的文件，不要和 E187 混成同一張清單。官方也沒有在公開頁寫「沒通過就一定取消訂單」；訂單後果要看你們的合約怎麼寫。本頁不臆測特定客戶的做法。

## 老闆要先準備什麼

在買標準、請人檢測或改設備之前，老闆可以先問自己這幾件事。這不是驗證清單，只是讓討論對得準。

1. **客戶要的到底是不是 E187，以及哪一版。** 把合約、問卷或來信裡的編號與年份對出來。不要只聽口頭說「要符合半導體資安標準」。
2. **我們提供的，是不是商店頁所稱的設備或服務。** 是設備本體、控制電腦、還是整合服務？有沒有 Windows 或 Linux 的運算裝置？有沒有其實屬於 PLC／SCADA、因而不在這份標準範圍裡的部分？
3. **現在拿得出哪些證據。** 例如作業系統是否仍有人支援、網路如何隔離與連線、端點如何防護、日誌能不能查。證據對得上標準要求到什麼程度，要對照標準本文，本頁不代替那一步。
4. **誰在公司內部簽字負責。** 技術單位可以準備說明，但對客戶承諾「我們符合」是公司的責任。還沒做到的項目，不要為了過關先勾「是」。客戶問卷怎麼處理，見[企業主資安幕僚](/advisor/)相關說明。
5. **時程與營運後果要先講清楚。** 若趕不上客戶指定的日期，要早點把「差在哪、補什麼、要多久」講成出貨與信任的語言，而不是只回一句「我們會盡力」。

標準本文、查核表和檢測方法，需向 SEMI 取得或依客戶指定的方式進行。本頁不提供盜用或轉述受保護的條款細節。

## 什麼時候該找外面的資安幕僚

當老闆需要有人把客戶的 E187 要求，翻成「在不在適用範圍、現在差在哪、會不會影響出貨或信任」，並排先後。幕僚不代替實驗室檢測，也不保證通過某一客戶的查核。見[企業主資安幕僚](/advisor/)。若同時面對法規人力或事件應變，再回到[該找誰](/guides/who-to-call/)。

## 常見問題

### SEMI E187 是不是法律，不做會被罰？

SEMI 說明這類標準是產業自願性的技術協議，不是政府法令。會不會變成你「非做不可」，通常要看客戶有沒有把它寫進合約或供應鏈要求，以及合約怎麼約定。本頁不代替合約解釋。

### 我們不是設備商，只是供應鏈裡的中小企業，跟我們有關嗎？

商店頁寫的適用對象，是向晶圓廠提供設備或服務的單位，例如設備供應商和系統整合商。若客戶把 E187 往下轉給你，仍要先核對：你提供的東西在不在適用範圍。不要看到「半導體」三個字就自動對號入座，也不要自動排除。

### 工廠裡的 PLC 或產線控制系統，是不是都要符合 E187？

商店頁寫明：不適用於 PLC、SCADA，以及透過感測與致動網路接在它們上面的裝置。適用的是設備上安裝 Windows 或 Linux 的運算裝置。個別裝置怎麼歸類，要對照標準本文與實際架構。

### 現在是不是已經改成有安全等級的新版？

截至本頁整理日（2026 年 11 月 16 日），SEMI 商店頁仍列 E187-0122 為現行版（Current）。公開的修訂提案不能當成已經生效的要求。之後請以客戶指定版本和 SEMI 商店頁當時標示為 Current 的版本為準。

### 沒通過 E187，訂單會不會被取消？

官方公開頁沒有寫這種一律的後果。會不會影響訂單、出貨或後續合作，要看你們和客戶的合約。本頁不臆測。

### 顧問能不能保證幫我們通過 E187？

不能做這樣的保證。幕僚可以協助老闆看懂範圍、整理現況和先後，但不代替標準本文，也不保證某一客戶的查核結果。見[企業主資安幕僚](/advisor/)。
