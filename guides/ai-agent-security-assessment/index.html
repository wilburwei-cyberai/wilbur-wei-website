導入 AI Agent 前要注意哪些資安風險？找誰評估？

導入 AI Agent，和讓員工用聊天工具問問題，不是同一件事。Agent 可能讀得到公司的信件、文件或客戶資料，也可能被接到可以寄信、改資料或啟動其他系統的工具。權限一旦給大，它被帶偏或自己判斷錯，影響的就是停工、資料外洩、罰則，以及客戶還信不信任你。

所以在正式上線前，先把「它能看到什麼、能做什麼、什麼事一定要人點頭、出事怎麼叫停」問清楚。本頁用老闆聽得懂的話，整理這些檢查項，並說明該找誰一起評估。本頁不推薦特定廠商，也不保證評估完就不會出事。

為什麼導入前要先看資安

AI Agent 會依目標自己規劃步驟、呼叫工具。若它被接到不該用的權限或工具，即使沒有人惡意操弄，模型也可能自信地講出錯誤內容，讓人跟著做了錯的決定。更常見的風險，是電子郵件、網頁或文件裡夾了指示，讓 Agent 偏離原本的任務，例如把不該外流的資料寄出去，或在不該動的系統上執行動作。

這些不是只有資訊部門才要煩惱的技術名詞。對老闆來說，就是：會不會停工、客戶資料會不會外洩、有沒有罰則或合約責任，以及客戶還信不信任你。

GUIDE

上線前建議先核對的幾件事

  1. 權限只給剛好夠用的。 不要因為「以後可能用得到」就一次開到最大。讀資料不必同時有改、刪或寄出的權限。
  2. 先列出它能看到哪些資料。 客戶資料、內部信件、財務或尚未公開的文件，若沒有必要，就不要讓它碰到。
  3. 先列出它能呼叫哪些工具、能做哪些動作。 不需要的工具不要接上去；避免給它「執行任意指令」這類沒有範圍的能力。
  4. 高影響的動作，要有人批准才執行。 例如對外寄信、改帳或刪資料、接到付款或下單相關系統。批准要留在系統裡，不能只靠模型自己決定可不可以做。
  5. 把來自信件、網頁、文件的內容當成不可信的輸入。 這些地方可能藏著會改寫 Agent 行為的指示。
  6. 動作要留紀錄，也要能叫停或還原。 出了事要查得出是誰、或哪個 Agent、在什麼時候做了什麼，並且有人能立刻停掉它、把影響範圍擋下來。
  7. 問清楚廠商和模型怎麼處理公司資料。 對話和文件會不會被拿去訓練、會留多久、會不會交給其他人，請對方用書面說明，並核對你能不能選擇退出。
  8. 先寫清誰負責、誰能叫停。 評估和上線的責任在公司，不會因為用了某一家廠商或某一個模型就自動移走。資訊人員、業務負責人和外面來幫忙看的人，各自做什麼要分清楚。
GUIDE

問資訊人員或廠商的清單

第一次討論，不必先交出機密。帶著行業、想讓 Agent 做的那一件事，以及你最擔心的營運後果，先問下面這些：

  • 這次試點，它會讀到哪些資料？有沒有客戶或未公開的內容？
  • 它現在接了哪些工具？能不能寄信、改檔、呼叫內部系統？
  • 哪些動作一定要人看過才能執行？批准紀錄留在哪裡？
  • 若信件、網頁或文件裡有異常指示，系統會怎麼處理？
  • 日誌能回溯到單一動作嗎？誰能叫停？做錯了怎麼還原或隔離？
  • 送到廠商或模型的資料，會不會用於訓練？保留多久？資料刪除怎麼約定？
  • 出了事，公司內部是誰簽字負責？
GUIDE

找誰評估

要找的是能把風險講成停工、罰則、商譽和客戶信任的人，並且願意依上面的清單，和資訊人員或廠商一項項核對。公司內部的資訊人員通常最清楚系統現況；若老闆需要有人幫忙看懂與排先後，可以請外面的資安幕僚或顧問一起看。決定和責任仍留在公司，外面的人不能代替公司依法應設置的內部職務。

QUESTIONS

常見問題

還沒正式上線、只是先試用，也要先評估嗎？

要。試用階段如果已經接到真實信件、客戶資料或可執行動作的工具，風險和正式上線是同一類。範圍可以先縮小，但權限、資料和「要不要人批准」這幾項，建議在接到真實環境前就問完。

提示注入是什麼？公司的信或網頁真的能讓 Agent 做錯事嗎？

提示注入是指：寫進信件、網頁或文件裡的指示，讓模型做出不是你原本要求的行為。它不必長得像攻擊指令，員工日常轉貼的內容也可能觸發意外結果。影響有多大，取決於 Agent 當時看得到什麼、做得出什麼。公開說明見文末來源。

哪些動作一定要人批准？

凡是做了就難收回，或會直接碰到客戶、金錢、對外通訊和重要資料的，都應先由人批准。例如對外寄信、刪改資料、接到下單或付款相關系統。批准應寫在系統流程裡，不要只交代「模型自己判斷」。

導入 AI Agent 的資安風險，該找誰評估？

先由了解公司系統的資訊人員，對照上面的清單盤點資料、工具和權限。若老闆需要有人把風險講成營運後果，並幫忙排先後，可以再請資安幕僚或顧問一起看。責任和簽字仍在公司。

評估完、控制都做了，是不是就不會出事？

不是。提示注入目前沒有可以完全防住的方法，模型也可能產出錯誤內容。評估的目的，是把權限和影響範圍先縮小，並讓公司在出事時有人能叫停、有紀錄可查。沒有人能保證零風險。
